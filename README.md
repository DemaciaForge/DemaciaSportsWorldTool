# DemaciaSportsWorldTool

运动世界校园版协议自动化工具。纯 Rust 单文件可执行程序，GUI / CLI 双模式。

> 本项目是 [NekoSportsWorldTool](https://github.com/YanamiNeko/NekoSportsWorldTool) 的衍生作品，
> 在原版基础上做了大幅精简与真实性改造。署名与许可证要求见文末。

改造依据与代码事实记录在 [docs/REALISM_FINDINGS_zh.md](docs/REALISM_FINDINGS_zh.md)。

## 相对上游的主要改动

这一版做了**减法**：删掉三条维护成本高、收益低的生成路径，只留下能通过服务端交叉校验的那一条。

### 删除的功能

| 功能 | 删除原因 |
|---|---|
| **路网（Road）模式** | 自带一套速度剖面与字段逻辑、不走统一装配器，等于维护两份实现 |
| **AI 运动** | 与跑步记录无关的另一类记录，协议与校验完全不同 |
| **高德自定义路线** | 依赖外部路径服务，且自带距离/圈数换算 |
| **灰绿混合配色** | 灰绿分段在详情页会显示为灰色轨迹，反而可疑 |
| **自定义开始时间** | 原版可以把记录排到前 3 天；现固定为「现在 − 用时」 |
| **读取学校配速范围** | 改为人工填写，避免规则变更导致程序失效 |

连带的 `crates/route-planner`（1757 行）、`src/amap.rs`、`src/ui/map.rs` 一并移除。

### 新增与修正

- **围栏三级取值**：`策略内嵌 > 独立接口 > 点位缓存`。原实现只在策略没给围栏时才调独立接口，
  导致策略自带围栏的学校反而拿不到围栏来摆正跑道直道
- **`isFixed` 原样回传**：点位颜色是「必经(黄)/普通(蓝)」分类，`isPass` 才是「已通过(绿)」，
  两者独立。曾为了凑「至少 2 个普通点」改写 `isFixed`，结果详情页出现 2 绿 3 橙
- **顺序跑模式**：服务端 `policy == 1` 的学校要求按点位编号依次经过，此时不拟合椭圆，
  直接把点位连成闭合环。服务端下发的点位数组**不保证有序**（实测 4、5、2、3、1），
  生成前按编号重排
- **海拔带逐次随机**：真人每条记录的海拔跨度都不同（实测 9.78 / 11.27 / 11.78 m）。
  固定跨度本身就是破绽——曾有 10 条记录海拔带全是 16.00，那是同一次手动区间的产物
- **定位节拍 5 秒**：真机定位回调严格 5 s 一拍，5 秒间隔占比 98–99%，偶发丢 1–2 拍变 10/15 s
- **冻结门禁**：读到 `freezeRunTime > 0` 直接拒绝提交。真实客户端此时「开始跑步」按钮是禁用的，
  冻结期内发包等于自曝
- **`faceCheck` 跟随 `faceVerify`**：学校没开人脸抽检时上报 `faceCheck=0`，不再声称做过不存在的校验
- **真实性自检 19 项**：提交前对轨迹做互校，不通过直接中止
- **本地提交台账**：服务端只保留最近 10 条记录，台账记下每次成功的 `rrid` / `uuid` / 起跑时刻
- **`obs-real`**：拉回自己历史记录的 OBS 原始轨迹，用于对照字段
- **`--dry-run` 真正可用**：原版帮助里写了这个开关但从未接线

## 功能

- **跑步**：一键全链（策略 → 打卡点 → 轨迹 → 提交 → OBS → 验证）
  - 轨迹按打卡点用 Catmull-Rom 连成闭合环，**必然经过**每个打卡点
  - 可选标准跑道规格（自动 / 200 / 300 / 400 / 自定义长度），用电子围栏把直道摆正到场地长边
  - **顺序跑学校**（`policy=1`）自动改走点位环：按编号 1→2→3→… 依次经过，不比椭圆拟合
  - 路线颜色固定全绿色
- **数据**：学期完成度、违规自查、申诉状态查询、排行榜（个人 / 班级 / 院系 × 日 / 月、室内榜、历史榜）
- **登录**：人机验证本地自动通过，会话失效自动重登
- **自动更新**：检查 / 下载 / 自替换并重启；启动检查模式可选（静默 / 询问 / 关闭）。
  详见 [检查更新](#检查更新)

界面共 7 个标签页：跑步 · 运动记录 · 数据 · 我的 · 设备信息 · 运行日志 · 关于。

## 技术特点

- 完整实现 NetSecKit 信封加密与响应解密，每个响应强制 RSA 验签（fail-closed）
- 人机验证（GT4 滑块 + PoW）全程本地完成，不依赖外部服务
- **生物力学自洽**：`v = cadence/60 × stride`，速度、步频、步幅三者恒等；步频在目标值附近做
  OU 波动，步幅由速度反解，因此服务端做步频×步幅交叉校验时对得上
- 轨迹生成器：打卡点拟合环 + 自然速度曲线 + 哨兵点 / 断崖 / 点位吸附
- 设备身份持久化（DeviceId / 安装时间 / MAC），稳定不易触发风控
- GUI 与 CLI 共用同一套协议层，数据文件互通

### 提交前自检（19 项）

`src/track/realism.rs` 会对生成的轨迹做互校，任一项不过就中止提交：

| 维度 | 检查项 |
|---|---|
| 速度 | 瞬时速度峰值、速度字段与位移的相关性、速度字段量纲 |
| 时间 | 采样间隔（>30 s 判异常） |
| 距离 | 路径长 vs 声明距离、逐点 `totalDis` vs 位移重算 |
| 步态 | 步幅均值 / 标准差 / 包络（0.5–1.7 m）、速度与步频相关性 |
| 步数 | 累计步数、10 秒窗口步数 vs 总数 |
| 几何 | 环线圆度 |
| 分段 | 10 秒窗口、60 秒分段的总量守恒 |

## 使用

双击 exe 进入 GUI。

### 第一次使用

1. 打开「我的」页，填手机号和密码登录（凭据只存本地）
2. 打开「设备信息」页，**填本校区坐标**（定位锚点）和城市。
   默认锚点是大连，不填会拒绝提交
3. 回「跑步」页。GUI 没有 dry-run 按钮，要自检请先用命令行
   `run --dry-run` 确认轨迹正常（见下）
4. 确认无误再点「开始跑步」

### 推荐的工作流

先只读、再实跑。前三个命令都不会提交任何跑步记录：

```bash
# ① 看学校配置：目标距离、是否顺序跑、有没有人脸、是否在冻结期
demaciasportsworldtool run --policy-only

# ② 违规自查：自己是否被标记
demaciasportsworldtool cheat

# ③ 有被标记的记录时，看复核意见
demaciasportsworldtool appeal --rrid <记录号> --details

# ④ 本地生成并自检（不登录、不联网、不上传），确认轨迹合法
demaciasportsworldtool run --dry-run --dist 2 --pace 420

# ⑤ 确认无误再真正提交
demaciasportsworldtool run --dist 2 --pace 420
```

### GUI 用法

「跑步」页从上到下：

| 控件 | 说明 |
|---|---|
| 距离范围 | 每次随机落在这个区间内，如 `2.0 - 2.5` 公里 |
| 配速范围 | 秒/公里，如 `390 - 480` 即 6:30–8:00 |
| 操场规格 | 留「自动」即可；顺序跑学校会自动改用点位环 |
| 手动海拔（米/区间） | **不建议用**，会把海拔带固定成一个跨度。详见[海拔](#海拔) |
| 基准海拔（米） | 本地地面常年读数，留空自动 |
| 海拔震荡（米） | 上下摆动的**半幅**，例如 ±3 m 就填 `3` |
| 人脸校验标记 | 学校没开人脸抽检时**取消勾选**，否则等于谎报做过校验 |
| 换一版 | 重新抽样距离与配速，不联网 |
| 开始跑步 | 真正提交 |

GUI **不提供** dry-run。想先验证轨迹合法性，用命令行
`demaciasportsworldtool run --dry-run`，它不登录、不联网、不上传。

### 具体怎么填

多数学校 `minDistance` 是 2000 m，按下面填即可：

| 控件 | 填什么 | 为什么 |
|---|---|---|
| 距离范围 | `2.2` 至 `2.7` | 留 200 m 余量。生成轨迹的实际路径比标称短 1%~3%，贴着 2000 填容易判里程不足 |
| 配速范围 | `360` 至 `480` | 即 6:00–8:00/km，多数学校的允许区间 |
| 操场规格 | `自动` | 顺序跑学校会自动改走点位环 |
| 手动海拔 | **留空** | 填了会把海拔跨度固定成一个数，是明显破绽 |
| 基准海拔 | 留空，或填当地地面高程 | 留空时每次随机取 9.2–12.4 m 的海拔带 |
| 海拔震荡 | 留空 | 同上 |
| 人脸校验标记 | **不勾** | 不勾 = 跟随学校 `faceVerify`；学校没开就报 0 |

改完先跑一次 `run --dry-run`，通过再提交。

如果提交报「里程不足」或「本次里程低于学校要求」，把距离范围两端都加大
0.2 km 再试。

提交过程约 10–30 秒，日志会实时显示策略、点位、轨迹、提交、OBS、验证各步。

### 全部 CLI 命令

```text
login --user <手机号> --pass <密码> [--remember]   登录；--remember 存凭据以便自动重登
logout                                            登出并清理本地会话

run                                              一键跑步（随机距离 / 配速）
run --dist 2 --pace 420                          指定 2 km、7:00/km
run --dry-run                                    仅本地构造与自检，不联网
run --policy-only                                只拉策略打印配置，不提交
run --altitude-base 15 --altitude-osc 3          指定基准海拔与震荡半幅
run --lat 39.4930 --lon 116.2550                 临时改定位锚点
run --seed 42                                    固定随机种子（复现用）

records                                          跑步记录列表
semester                                         学期完成度
cheat [--page n]                                 违规自查
appeal --rrid <id> [--details]                   申诉状态 / 设备取证详情
rank main --type 1 --sort 1                      排行榜（1个人 2班级 3院系；1日 2月）
rank indoor --range 1                            室内榜
rank history --sort 1                            历史榜

obs-real [--rrid n]                              拉回真实 OBS 原始轨迹
ledger [--all] [--hint]                          本地提交台账
template --file run.gpx                          本地分析真实记录海拔
update [--check]                                 检查更新
help                                             全部命令
```

### 起跑时刻

固定为「现在 − 用时」。例如 14:40 提交一条 23 分钟的跑步，记录的就是 14:17–14:40。
**不支持**把记录排到过去的任意时刻。

### 海拔

界面上有两个输入框：**基准海拔**和**海拔震荡**，都留空时自动。

| 输入 | 行为 |
|---|---|
| 基准海拔留空、震荡留空 | 每次按记录种子随机取 9.2–12.4 m 的海拔带 |
| 基准海拔填数字（如 `15`） | 曲线以该高度为中线 |
| 震荡填数字（如 `3`） | 上下摆动的**半幅**，即总跨度约 6 m |

**不要用「固定跨度」的方式控制海拔。** 真人每条记录的海拔跨度都不一样，如果每次提交都是
同一个跨度（例如都填 `6-22`，跨度恒为 16.00），这在服务端看来是一眼假的参数异常。

同理，「手动海拔」输入一个固定值（所有点同高）也不是真实形态——真机高程始终在波动，
只是幅度不大。要看绝对高度对得上，填基准海拔即可；要精确压平曲线，才用固定值。

`--altitude` / 区间形式的 `--altitude 6-22` 仍保留兼容，但它把曲线**映射到一个固定跨度**，
每次提交的跨度都一样。**日常不要用**，除非是配合 `template` 分析历史记录。

CLI 等效写法：

```bash
demaciasportsworldtool run --altitude-base 15          # 基准 15 m，震荡自动
demaciasportsworldtool run --altitude-base 15 --altitude-osc 3   # 基准 15 m，上下各 3 m
```

### 冻结

服务端在策略响应里下发 `freezeRunTime`（秒）。大于 0 表示账号处于跑步冻结期，
程序会打印剩余时长并拒绝提交，不会向服务端发任何东西。

真实客户端在冻结期内「开始跑步」按钮是禁用的，所以冻结期里本来就不该有任何提交。
冻结期强行发包，服务端看到的就是「封禁账号仍在提交记录」。

### 只读查询

三个命令可以确认学校配置和账号状态，**都不会提交任何跑步记录**：

```bash
# 只拉策略，打印配置后退出。不生成轨迹、不拉点位、不上传 OBS、不提交
demaciasportsworldtool run --policy-only

# 违规自查：自己是否被标记，以及全校违规名单
demaciasportsworldtool cheat

# 申诉状态 + 设备取证详情（抓拍照片清单）
demaciasportsworldtool appeal --rrid 1344964947 --details
```

`--policy-only` 的输出里有几个关键字段：

| 字段 | 含义 |
|---|---|
| `目标距离` | 本次跑步至少要跑多少米（`runRuleModel.minDistance`） |
| `点位模式` | 顺序跑 / 随机点位，看的是 **`policy`**（1 = 顺序），不是 `sequenceRule` |
| `人脸抽检` | 学校是否开人脸；决定提交体的 `faceCheck` 是 1 还是 0 |
| `跑步冻结` | `freezeRunTime`，大于 0 就是冻结中，剩余秒数 |
| `必经点位` | 服务端下发的必经点数量 |

冻结期间服务端会返回 `runRuleModel: null`，此时拿到的 `policy` / `target` 都不可信——
那是「不让你跑」的意思，不是学校没有规则。要判断真实配置，得等解冻后再查。

### 检查更新

界面**最下方**有「检查更新」按钮，右侧显示当前版本号。检查结果直接显示在左下角状态栏
（`已是最新版本` / `发现新版本 vX.Y.Z` / `检查更新失败…`）。

**启动时**也可自动检查，`config.json` 的 `update_check` 有三种取值：

| 值 | 行为 |
|---|---|
| `silent`（默认） | 静默检查，只有发现新版本才弹窗 |
| `ask` | 每次启动询问 |
| `off` | 完全不检查 |

更新源是 `api.github.com/repos/DemaciaForge/DemaciaSportsWorldTool/releases/latest`，
**匿名请求**，不携带账号令牌。因此本仓库必须保持 **public**，否则匿名读不到发布信息。

发布资产名是固定的，改名会导致更新失败。**目前只发布 Windows x64 包**，
macOS / Linux / Android 目标已从 CI 移除：

| 平台 | 资产名 |
|---|---|
| Windows x86_64 | `DemaciaSportsWorldTool-win-x64.zip` |

程序会从 zip 里找 `*.exe`（打包带 `target/` 路径也能识别），下载后自替换并重启。
网络不通时可到 [Releases](https://github.com/DemaciaForge/DemaciaSportsWorldTool/releases)
手动下载：退出程序，用新的 `demaciasportsworldtool.exe` 覆盖旧的，**保留**
`config.json`、`identity.json`、`points_cache.json` 等数据文件。

调试时可用环境变量 `NSWT_UPDATE_REPO` 临时指向别的仓库（如自己的测试 fork）。

### 青龙定时任务

首次手工 `login --remember` 一次，之后定时挂 `run` 即可。

## 数据文件

全部存放在**可执行文件同目录**：

| 文件 | 内容 | 能否删除 |
|---|---|---|
| `config.json` | 界面与参数配置（含勾选记住密码后的明文凭据） | 可删，会重置配置 |
| `identity.json` | 设备身份与定位锚点 | **不要删**，等于换新设备 |
| `session.json` | 登录会话 | 可删，需重新登录 |
| `points_cache.json` | 打卡点与围栏缓存 | 可删，会重新拉取 |
| `submitted_records.jsonl` | 本地提交台账 | 建议保留 |

## 常见问题

- **提示未登录 / 401**：先 `login --remember`，会话失效会自动重登
- **`10121` 设备风险**：设备身份是持久化的，删 `identity.json` 等于换了新设备，不要频繁删
- **`10603` 点位限流**：点位接口 5 分钟限 3 次，程序内置 300 秒缓存
- **提示「请先在设备信息页填写城市和定位锚点」**：默认锚点是大连，首次使用需在「设备信息」页
  填本校区坐标，否则拒绝提交
- **榜单为空**：当天还没有人产生有效里程，查询会自动回退最近 3 天
- **提示「账号处于跑步冻结期」**：账号被服务端冻结，`run --policy-only` 可看剩余时长。
  冻结期内不要提交，真实客户端此时同样发不出跑步
- **记录被判「APP参数数据异常」**：这类结论来自人工复核，指向提交参数而不是轨迹本身。
  常见成因是参数过于规整（例如每次海拔跨度完全相同、采样间隔规律性抖动）
- **`10175` 账号或密码错误**：服务端会累计失败次数，约 5 次后锁定 1 小时。
  密码不确定时先在手机 App 上试，不要反复用程序试
- **检查更新失败**：更新仅直连 GitHub，网络不通时到 Release 页手动下载
- **人机验证失败**：自动重试 3 轮，仍失败多为网络波动
- **杀软误报**：未签名编译产物可能被误报，自行判断后加白

## 构建

```bash
cargo build --release                         # GUI + CLI
cargo build --release --no-default-features   # 仅 CLI
```

**注意**：`--no-default-features` 会把 GUI 关掉，产物双击无参数只打印用法后立即退出。
要跑 CLI 调试又不覆盖 GUI 产物时，用独立 target 目录：

```bash
cargo build --no-default-features --target-dir target/cli
```

测试：

```bash
cargo test --workspace     # 144 项
```

推 tag 自动构建多平台产物并发布 Release（见 `.github/workflows/release.yml`）。
